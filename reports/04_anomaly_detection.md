# Anomaly detection

## Цель
Выявлять аномальные всплески событий контроля качества
для пар «производитель + препарат».

## Единица анализа
Одна строка = производитель + препарат + месяц.

## Базовый метод
- Baseline: медиана числа событий за предыдущие 12 месяцев.
- Разброс: MAD за предыдущие 12 месяцев.
- Robust z-score: (текущее значение - медиана) / (1.4826 * MAD).
- Аномалия: robust z-score >= 3.5 и минимум 2 события в месяце.

## Дополнительный метод
Isolation Forest по временным и объёмным признакам.
Порог contamination = 0.02.

## Ограничения
- Метод выявляет статистические всплески, а не автоматически подтверждает недоброкачественность.
- Для объектов с короткой историей anomaly detection не применяется.
- Порог требует калибровки по precision@K и review sample.

## Результаты первой итерации

- Robust rule: 4 029 аномалий.
- Isolation Forest при contamination=0.02: 16 968 наблюдений.
- Пересечение: 4 029 наблюдений.
- Все robust-аномалии покрыты Isolation Forest.
- Isolation Forest использует более широкий критерий «необычности»,
  поэтому его флаг не следует использовать как самостоятельный вердикт.
- Для сопоставимого сравнения необходимо использовать одинаковый бюджет алертов,
  например top-5 000 по anomaly score.
- Модель Isolation Forest должна обучаться только на исторических месяцах,
  чтобы исключить утечку информации из будущего.
